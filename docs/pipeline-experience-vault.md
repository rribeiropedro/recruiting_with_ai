## 1. Purpose & Concept

The Experience Vault replaces the static PDF resume with a queryable database. Every piece of a user's professional history is stored as an independent, atomic **node** — one project, one role, one certification. Nodes are tagged with keywords, embedded as vectors, and retrievable via semantic similarity by downstream modules (Semantic Matcher, Document Assembly).

### 1.1 What Constitutes a Node

One node = one distinct professional experience. Granularity rules:

- If a user held **one role** but worked on **three separate projects**, that is **three nodes** sharing the same `organization` and `role` but with different `title`, `description`, and `bullet_points`.
- A four-year degree is **one node** of type `education`.
- A certification is **one node** of type `certification`.
- A hackathon where the user built a specific project is **one node** of type `hackathon`.

The goal is maximum retrieval granularity — downstream modules can cherry-pick the 4-5 most relevant nodes for any given job, rather than including everything.

## 2. Database Schema

### 2.1 `experience_nodes` Table

```sql
CREATE TABLE experience_nodes (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,

    -- Content fields (user-supplied)
    title           TEXT NOT NULL,                          -- "Distributed Cache Layer for HPC Cluster"
    organization    TEXT,                                   -- "Virginia Tech CS Department"
    role            TEXT,                                   -- "Research Assistant"
    start_date      DATE,
    end_date        DATE,                                   -- NULL = ongoing
    description     TEXT NOT NULL,                          -- Full prose description (1-3 sentences)
    bullet_points   JSONB NOT NULL DEFAULT '[]',            -- ["Designed X using Y", "Reduced Z by 40%"]
    node_type       TEXT NOT NULL CHECK (node_type IN (
                        'work', 'research', 'project', 'hackathon',
                        'certification', 'education', 'leadership', 'volunteer'
                    )),

    -- Metadata (auto-generated by background tasks)
    tags            TEXT[] DEFAULT '{}',                    -- ["python", "hpc", "distributed-systems"]
    embedding       vector(1536),                          -- pgvector column, NULL until embedded

    -- Housekeeping
    source          TEXT DEFAULT 'manual' CHECK (source IN ('manual', 'bulk_import')),
    is_archived     BOOLEAN DEFAULT FALSE,                 -- Soft delete
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_nodes_embedding ON experience_nodes
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64);

CREATE INDEX idx_nodes_user ON experience_nodes(user_id);
CREATE INDEX idx_nodes_type ON experience_nodes(user_id, node_type);
CREATE INDEX idx_nodes_tags ON experience_nodes USING gin(tags);
CREATE INDEX idx_nodes_archived ON experience_nodes(user_id, is_archived);
```

### 2.2 RLS Policy

```sql
ALTER TABLE experience_nodes ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can only access their own nodes"
    ON experience_nodes FOR ALL
    USING (auth.uid() = user_id)
    WITH CHECK (auth.uid() = user_id);
```

### 2.3 Updated-At Trigger

```sql
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_nodes_updated_at
    BEFORE UPDATE ON experience_nodes
    FOR EACH ROW EXECUTE FUNCTION update_updated_at();
```

## 4. API Endpoints

Base path: `/vault`

### 4.1 Create Node

```
POST /vault/nodes
Auth: Required
Body: NodeCreateRequest
Returns: 201 + NodeResponse
Side effects: Dispatches tag_node_task → embed_node_task chain
```

**Implementation notes:**
- Insert row with `embedding = NULL`, `tags = '{}'`.
- Dispatch Celery chain: `tag_node_task.si(node_id) | embed_node_task.si(node_id)`.
- Return immediately — don't wait for tasks.

### 4.2 List Nodes

```
GET /vault/nodes?type={node_type}&search={keyword}&cursor={uuid}&limit={int}
Auth: Required
Returns: 200 + NodeListResponse
```

**Query parameters:**
- `type` (optional): Filter by `node_type`.
- `search` (optional): Full-text search against `title`, `description`, `tags` (use `ILIKE` or `tsvector`).
- `cursor` (optional): UUID of last node from previous page.
- `limit` (optional, default 20, max 50): Page size.

**SQL pattern:**

```sql
SELECT * FROM experience_nodes
WHERE user_id = $1
  AND is_archived = FALSE
  AND ($2::text IS NULL OR node_type = $2)
  AND ($3::text IS NULL OR (
      title ILIKE '%' || $3 || '%'
      OR description ILIKE '%' || $3 || '%'
      OR $3 = ANY(tags)
  ))
  AND ($4::uuid IS NULL OR created_at < (SELECT created_at FROM experience_nodes WHERE id = $4))
ORDER BY created_at DESC
LIMIT $5;
```

### 4.3 Get Single Node

```
GET /vault/nodes/{id}
Auth: Required
Returns: 200 + NodeResponse
Errors: 404 if not found or not owned by user
```

### 4.4 Update Node

```
PUT /vault/nodes/{id}
Auth: Required
Body: NodeUpdateRequest (partial update — only supplied fields change)
Returns: 200 + NodeResponse
Side effects: If any content field changed (title, description, bullet_points, role, organization),
              re-dispatch tag_node_task → embed_node_task chain
```

**Content field change detection:** Compare old values to new values. If `title`, `description`, `bullet_points`, `role`, or `organization` changed, clear existing `tags` and `embedding` and re-dispatch the chain. If only metadata fields changed (dates, node_type), skip re-processing.

### 4.5 Delete (Archive) Node

```
DELETE /vault/nodes/{id}
Auth: Required
Returns: 204
Action: SET is_archived = TRUE (never hard-delete)
```

### 4.6 Bulk Import

```
POST /vault/bulk-import
Auth: Required
Body: BulkImportRequest
Returns: 202 + { task_id: str }
Side effects: Dispatches bulk_import_task
```

### 4.7 Bulk Import Status

```
GET /vault/bulk-import/{task_id}
Auth: Required
Returns: 200 + BulkImportStatusResponse
```

## 5. Background Tasks

### 5.1 `tag_node_task`

| Property | Value |
|---|---|
| Queue | `default` |
| Typical duration | 2-5s |
| Retry policy | 3 retries, exponential backoff (5s, 15s, 45s) |
| Idempotent | Yes — overwrites `tags` column |

**Logic:**

```python
@celery_app.task(bind=True, max_retries=3, default_retry_delay=5)
def tag_node_task(self, node_id: str):
    node = db.get_node(node_id)  # Uses service_role key
    if not node:
        return  # Node was deleted before task ran

    prompt_text = f"{node.title}\n{node.description}\n{' | '.join(node.bullet_points)}"

    tags_json = llm_client.complete(
        system_prompt=TAG_NODE_SYSTEM_PROMPT,
        user_prompt=prompt_text,
        model="claude-haiku-4-5-20251001",
        response_format="json",
        user_id=node.user_id,
        task_type="tag",
        prompt_version=TAG_NODE_VERSION,
    )

    try:
        tags = json.loads(tags_json)
        assert isinstance(tags, list)
        assert all(isinstance(t, str) for t in tags)
    except (json.JSONDecodeError, AssertionError):
        # Retry once with stricter instruction
        if self.request.retries < 1:
            raise self.retry(countdown=5)
        tags = []  # Give up, node is still usable without tags

    db.update_node(node_id, tags=tags)
```

### 5.2 `embed_node_task`

| Property | Value |
|---|---|
| Queue | `default` |
| Typical duration | 1-3s |
| Retry policy | 3 retries, exponential backoff (10s, 30s, 90s) |
| Idempotent | Yes — overwrites `embedding` column |

**Logic:**

```python
@celery_app.task(bind=True, max_retries=3)
def embed_node_task(self, node_id: str):
    node = db.get_node(node_id)
    if not node:
        return

    embedding_text = build_embedding_text(node)
    vector = llm_client.embed(embedding_text, user_id=node.user_id)
    db.update_node(node_id, embedding=vector)
```

**Embedding text construction:**

```python
def build_embedding_text(node) -> str:
    parts = [node.title]
    if node.organization:
        parts.append(f"at {node.organization}")
    if node.role:
        parts.append(f"as {node.role}")
    parts.append(node.description)
    parts.extend(node.bullet_points)
    return " | ".join(parts)
```

### 5.3 `bulk_import_task`

| Property | Value |
|---|---|
| Queue | `heavy` |
| Typical duration | 30-120s |
| Retry policy | 1 retry |
| Idempotent | Yes — deduplicated by `(user_id, storage_path)` unique constraint |

**Logic:**

1. Download PDF from Supabase Storage.
2. Extract text using `pdfplumber` (preferred) or `PyMuPDF`.
3. Call Claude Sonnet with `BULK_IMPORT_SYSTEM_PROMPT` to decompose into nodes.
4. Parse the JSON response into a list of node objects.
5. For each node: check for an existing row with `(user_id, storage_path, source='bulk_import')` — if found, skip to avoid duplicates on retry. Otherwise insert with `source = 'bulk_import'`, then chain `tag_node_task | embed_node_task`.
6. Use a Celery `chord` to track completion of all child tasks.
7. Update the bulk import status to `completed` with `nodes_created` count.

**Deduplication:** Add a unique partial index to guard against duplicate imports on retry:

```sql
CREATE UNIQUE INDEX idx_nodes_bulk_import_dedup
    ON experience_nodes (user_id, (metadata->>'storage_path'))
    WHERE source = 'bulk_import';
```

Store the `storage_path` as `metadata->>'storage_path'` on each node created by a bulk import so the index can enforce uniqueness.

**Failure handling:**

- If PDF extraction fails → fail the task with message "Could not extract text from PDF".
- If LLM parsing fails → retry once. If still fails → fail the task.
- If individual node creation fails → skip that node, continue with others, report partial completion.

## 6. LLM Prompts

### 6.1 `tag_node.py`

```python
VERSION = "tag_v1"

SYSTEM_PROMPT = """You are a metadata tagging engine for professional experience entries.
Given a professional experience description, extract relevant keyword tags.

Return ONLY a JSON array of lowercase strings. No explanation, no markdown.

Categories to extract:
- Programming languages (e.g., "python", "c++", "javascript")
- Frameworks & libraries (e.g., "react", "django", "pytorch")
- Tools & platforms (e.g., "docker", "aws", "git")
- Technical concepts (e.g., "distributed-systems", "machine-learning", "hpc")
- Domains (e.g., "fintech", "healthcare", "robotics")
- Methodologies (e.g., "agile", "ci-cd", "test-driven-development")
- Soft skills only if prominently featured (e.g., "leadership", "cross-functional")

Rules:
- Use lowercase, hyphenated multi-word tags (e.g., "machine-learning" not "Machine Learning")
- 5-15 tags per entry
- Only extract what is explicitly stated or strongly implied
- Do NOT infer technologies not mentioned

Example output: ["python", "distributed-systems", "hpc", "mpi", "c", "performance-optimization"]"""
```

### 6.2 `bulk_import.py`

```python
VERSION = "bulk_import_v1"

SYSTEM_PROMPT = """You are a resume parser. Given the full text of a resume, decompose it into
individual professional experience nodes. Each node represents ONE distinct experience
(one project, one role, one certification, one degree).

Return ONLY a JSON array of objects. No explanation, no markdown fences.

Each object must have these fields:
- "title" (string): Name of the project, role, or experience. Be specific.
- "organization" (string or null): Company, university, or org name.
- "role" (string or null): Job title or position held.
- "start_date" (string "YYYY-MM" or null): When this started.
- "end_date" (string "YYYY-MM" or null): When this ended. null = ongoing.
- "description" (string): 1-2 sentence summary of the experience.
- "bullet_points" (string[]): Achievement-oriented bullets. Start with action verbs.
  Preserve all numbers, percentages, and metrics exactly as stated.
- "node_type" (string): One of "work", "research", "project", "hackathon",
  "certification", "education", "leadership", "volunteer".

CRITICAL RULES:
1. Do NOT invent or embellish any detail. Only extract what is explicitly stated.
2. If a single role involved multiple distinct projects, create SEPARATE nodes for each project.
3. Preserve all quantitative claims exactly (e.g., "reduced latency by 40%").
4. If something is ambiguous, use the most conservative interpretation.
5. Education entries should use node_type "education" with the degree as title.
6. Certifications should use node_type "certification"."""
```

## 7. Frontend Specification

### 7.1 Pages

**`app/(auth)/vault/page.tsx`** — Node list view

**Empty state (0 nodes):**

Show a centered explanation panel — not a blank screen:

```
Your Vault is empty

Instead of one static resume, your Vault stores each project, role,
and achievement separately. For every job you apply to, we pick the
5 most relevant pieces and tailor them to that job's language.

[+ Add your first experience]   [Import from resume PDF]
```

This explanation is shown only when `nodes.length === 0`. Once the user has at least one node, replace it with the normal list.

**Normal state (≥1 nodes):**

- Display all non-archived nodes in a card grid or list.
- Each card shows: title, organization, role, date range, node type badge, tags as pills.
- **Embedding status:** Only show a status indicator when something requires user attention. Do not show a green "embedded" dot as a routine UI element — it surfaces internal pipeline state that users don't care about. Show only:
  - A subtle spinner (animated ring) on the card for up to 30 seconds after creation while processing.
  - A red "!" badge if embedding permanently failed, with a tooltip "Processing failed — this node won't be matched to jobs. Try editing and saving again."
- Filter bar: dropdown for `node_type`, text search input.
- Pagination: "Load more" button (cursor-based).
- Actions: "Add Node" button → modal or new page. "Import Resume" button → file upload modal.

**`app/(auth)/vault/new/page.tsx`** — Node creation form

- Fields: title (text), organization (text), role (text), start date (date picker), end date (date picker + "ongoing" checkbox), description (textarea), bullet points (dynamic list — add/remove bullets), node type (dropdown).
- Validation: client-side via `zod` matching the Pydantic schema.
- **Granularity helper text** — shown inline beneath relevant fields to prevent the most common mistake (creating one giant "work experience" node instead of per-project nodes):
  - Under **Title**: placeholder text `e.g. "Real-Time Analytics Dashboard"` (not "Software Engineer at Acme"). Helper: "Name the specific project or experience, not your job title."
  - Under **Description**: "Describe this specific project or role — what you built, why it mattered."
  - Below the form header: a dismissible callout: "One node = one distinct thing you built or did. If a job had three projects, create three nodes — we pick the most relevant ones for each application."
- On submit: `POST /vault/nodes`. Show success toast. Redirect to vault list.

**`app/(auth)/vault/[id]/page.tsx`** — Node edit view

- Same form as creation, pre-populated.
- On submit: `PUT /vault/nodes/{id}`. Show toast indicating if re-embedding was triggered.
- Delete button: confirmation modal → `DELETE /vault/nodes/{id}`.

**`app/(auth)/vault/import/page.tsx`** — Bulk import flow

- File upload dropzone (accept `.pdf` only, max 10MB).
- Upload to Supabase Storage, then `POST /vault/bulk-import`.
- Progress UI: poll `GET /vault/bulk-import/{task_id}` every 3 seconds. Show stages: "Uploading → Parsing resume → Analyzing experiences → Ready to review".

**Review step (required before committing nodes):**

After the LLM decomposition completes, do NOT immediately insert nodes into the Vault. Instead:

1. Return the proposed nodes as a JSON array from a new `GET /vault/bulk-import/{task_id}/preview` endpoint.
2. Show the user a review screen with one editable card per proposed node:
   - Each card shows: title, organization, role, date range, node type, bullet points.
   - Inline editing for all fields.
   - A "Remove" button per card.
   - A "Split into two nodes" action (for cases where the LLM combined two projects).
3. At the bottom: "Import X nodes" primary button, "Cancel" link.
4. On confirm: `POST /vault/bulk-import/{task_id}/commit` with the (possibly edited) node array. This triggers the actual DB inserts + tag/embed tasks.

This prevents bad LLM decomposition from silently polluting the Vault. The review step is not optional — the user must explicitly confirm before nodes are created.

**Backend additions required:**
- `GET /vault/bulk-import/{task_id}/preview` — returns proposed nodes without inserting them; store the LLM output in a temp Redis key (TTL 30 min) keyed by `task_id`.
- `POST /vault/bulk-import/{task_id}/commit` — accepts the reviewed node array and performs the actual inserts.

## 9. Edge Cases & Error Handling

| Scenario | Handling |
|---|---|
| User creates node with empty bullet_points | Allowed — description alone is embeddable |
| Embedding API is down | Task retries 3x. After final failure, node exists with `embedding = NULL`. Background recovery job runs every 15 min to re-attempt. |
| Tag LLM returns invalid JSON | Retry once with stricter instruction appended. If still fails, set `tags = '{}'`. Node is usable without tags. |
| User updates only the start_date | No re-embedding triggered (non-content field). |
| User updates the description | Clear `tags` and `embedding`, re-dispatch chain. |
| Bulk import PDF has no extractable text (scanned image) | Fail with message "Could not extract text — try a text-based PDF or enter nodes manually." |
| Bulk import LLM returns 0 nodes | Fail with message "No professional experiences found in this document." |
| User deletes a node that is referenced by a `generated_applications.matched_node_ids` | Soft-delete only. The generated application retains the reference; the `tailored_content` JSONB has the snapshot. |
| Concurrent updates to same node | Last write wins. `updated_at` trigger ensures timestamp accuracy. |

## 10. Data Flow to Other Modules

The Vault does not depend on any other pipeline. Other pipelines depend on the Vault:

- **Semantic Matcher** reads `experience_nodes` via the vector similarity query (`embedding <=> $1::vector`). The Matcher only reads — it never writes to `experience_nodes`.
- **Document Assembly** reads matched nodes by ID to get the full `bullet_points` and `description` for rewriting. It also never writes to `experience_nodes`.

The Vault's only outbound contract is the `ExperienceNodeResult` shape defined in `architecture.md` section 3.5.
